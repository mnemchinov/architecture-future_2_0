# Роадмап изменений технологического ландшафта

**Компания «Будущее 2.0» | 12 месяцев | Привязка к бизнес-целям**

---

## Этап 1. Фундамент — облачная миграция и границы доменов

**Период:** 0–3 месяца

| Аспект | Описание |
|--------|----------|
| **Бизнес-цель** | Обеспечить инфраструктурную базу для независимого развития доменов |
| **Шаги по порталу** | Концепция и архитектура портала самообслуживания, выбор стека (React, Node.js) |
| **Независимость подразделений** | Формирование команд доменов, выделение operational data stores (PostgreSQL/YDB), настройка IAM и сетей |
| **Качество сервисов** | Базовая безопасность: IAM-политики, изоляция сетей (VPC), базовое логирование |

### Ожидаемые результаты

- Развёрнута **cloud landing zone** в Yandex Cloud (VPC, Managed K8s, Object Storage, Managed Databases)
- Созданы **команды 5 доменов** с выделенными средами разработки
- Определены **data contracts** (пилотный формат) для междоменного обмена
- Запущен **пилот миграции**: выгрузка одного датасета из SQL Server 2008 в Object Storage (Iceberg)

### Ответственные команды

- **DevOps / Cloud** — настройка cloud landing zone, K8s, CI/CD
- **Архитекторы** — границы доменов, data contracts
- **Инфраструктура** — миграция сетей, IAM

### Необходимые ресурсы

- 2 DevOps-инженера (Yandex Cloud, K8s)
- 1 архитектор данных
- Бюджет на облачные ресурсы Yandex Cloud (стартовый)

### Бизнес-обоснование

**Влияние на скорость принятия решений:** Cloud landing zone сокращает время развёртывания новых сред с недель до часов.

**Снижение затрат:** Уход от физических серверов (CAPEX → OPEX).

## Этап 2. Платформа данных — Data Lakehouse и витрина

**Период:** 3–6 месяцев

| Аспект | Описание |
|--------|----------|
| **Бизнес-цель** | Снизить зависимость от legacy DWH, ускорить отчётность |
| **Шаги по порталу** | Разработка бэкенда портала (API Gateway + data catalog) |
| **Независимость подразделений** | Каждый домен публикует data products в Lakehouse, настраивает свои pipelines |
| **Качество сервисов** | Мониторинг data quality, пилот data contracts |

### Ожидаемые результаты

- Запущен **Data Lakehouse** (Apache Iceberg на Object Storage) — единое аналитическое хранилище
- Развёрнут **ClickHouse** как fast-query слой для витрины данных
- Внедрён **Kafka** как событийная шина — все домены публикуют события
- **Legacy DWH** переведён в режим read-only + периодическая выгрузка в Lakehouse
- **3 домена** (Medical, Fintech, AI) публикуют первые data products
- **Отчёты в Power BI** переключены на ClickHouse (время построения: с часов до минут)

### Ответственные команды

- **Data Platform** — Lakehouse, ClickHouse, Kafka
- **Доменные команды** — pipelines, data products
- **BI-разработчики** — переключение дашбордов на ClickHouse

### Необходимые ресурсы

- 2 Data-инженера (Iceberg, Kafka, Airflow)
- 1 DevOps (ClickHouse, мониторинг)
- Дополнительные облачные ресурсы (Managed Kafka, Object Storage)

### Бизнес-обоснование

**Скорость:** Отчёты строятся за минуты вместо часов — ускорение принятия управленческих решений.

**Независимость:** Новая бизнес-логика не требует правок в DWH — реализуется в домене сразу.

**Качество:** Data contracts гарантируют совместимость data products между доменами.

## Этап 3. Портал самообслуживания и ИИ-конвейер

**Период:** 6–9 месяцев

| Аспект | Описание |
|--------|----------|
| **Бизнес-цель** | Бизнес-пользователи самостоятельно работают с данными; ИИ-аналитика в production |
| **Шаги по порталу** | Запуск self-service portal: каталог data products, визуализация, дашборды |
| **Независимость подразделений** | Партнёрский домен запускает интеграцию; ИИ-домен деплоит модели в clinic workflows |
| **Качество сервисов** | Регуляторная отчётность (ЦБ, 152-ФЗ) автоматизирована через Lakehouse |

### Ожидаемые результаты

- Запущен **Self-Service Data Portal**:
  - Каталог data products (по доменам)
  - Встроенные дашборды на Apache Superset (self-service BI)
  - Поиск и запрос доступа к данным
- **ИИ-конвейер** в production: Kubeflow/Airflow пайплайны, модель диагностики на потоке
- **Партнёрский домен** подключил первого партнёра (фармацевтика) через data products
- **Управленческая отчётность** полностью формируется из Lakehouse (без DWH)

### Ответственные команды

- **Portal Team** (React/Node.js) — разработка портала
- **ML/DS** — Kubeflow, деплой моделей
- **Partner Integration** — подключение партнёров
- **Governance** — управленческие дашборды

### Необходимые ресурсы

- 2 Frontend (React), 2 Backend (Node.js) — портал
- 1 ML-инженер (Kubeflow)
- 1 интеграционный разработчик
- Дополнительные облачные GPU-ресурсы для ИИ

### Бизнес-обоснование

**Качество сервиса:** ИИ-диагностика повышает точность постановки диагнозов.

**Масштабирование:** Партнёрский домен подключает новых партнёров без доработки других доменов.

**Скорость:** Бизнес-пользователи находят и потребляют данные самостоятельно — без запросов в ИТ.

## Этап 4. Оптимизация и масштабирование

**Период:** 9–12 месяцев

| Аспект | Описание |
|--------|----------|
| **Бизнес-цель** | Полный переход на целевую архитектуру, масштабирование на новые направления |
| **Шаги по порталу** | Ролевая модель, аудит доступа, расширенная аналитика |
| **Независимость подразделений** | Все 5 доменов работают независимо, публикуют и потребляют data products |
| **Качество сервисов** | 100% автоматизация регуляторной отчётности, SLA-мониторинг |

### Ожидаемые результаты

- **Legacy DWH (SQL Server 2008)** полностью выведен из эксплуатации (только бэкапы)
- **PowerBuilder** замещён порталом для всех ключевых сценариев (регистратура, расписание)
- **5 доменов** в полной автономии: собственные CI/CD, data products, API
- **Apache Camel (ESB)** замещён Kafka + Kong для всех интеграций
- **SLA-мониторинг** качества данных и времени отклика сервисов
- **Партнёрский домен** обслуживает 3+ партнёров

### Ответственные команды

- **Все доменные команды** — поддержка и развитие
- **DevOps** — инфраструктура, SLA, мониторинг
- **Security / Compliance** — аудит, сертификация

### Необходимые ресурсы

- 1 SRE-инженер (мониторинг, SLA)
- 1 Security-специалист (аудит, 152-ФЗ)
- Бюджет на финальную миграцию legacy

### Бизнес-обоснование

**Снижение затрат:** Отказ от SQL Server 2008 и PowerBuilder сокращает лицензионные расходы и стоимость поддержки.

**Качество:** Полная регуляторная отчётность в автомате — исключены человеческие ошибки.

**Масштабирование:** Архитектура готова к подключению любых новых бизнесов — просто создать data product в существующем или новом домене.
